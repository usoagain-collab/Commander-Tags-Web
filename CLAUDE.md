# Deck Genome (repo: Commander Tags Web)

A Commander (EDH) deck builder where **Scryfall Tagger tags drive everything**: auto-categories, a role profile with target sliders, and card suggestions ranked by how well a card's tags fit the deck. The bet: suggesting cards by *function* (what a card does) beats EDHREC-style suggestions by *popularity*.

- **Name (David, Nov 2, 2026): the site is called "Deck Genome"** (deckgenome.com). Use that name in anything users see. The repo, the Vercel project `commandertagsweb`, the npm package name and the test account email keep the old name on purpose.
- Full feature spec: `docs/spec.md`, the source of truth for what to build.
- Working prototype: `prototype/tag-deck-builder.html`, a single HTML file with the tag logic already proven. Port its logic; don't re-invent it.

## Phase 3 plan (agreed Oct 18, 2026)

- **Computed in the browser**, ported from the prototype into tested TypeScript modules. The **oracle tag tree** (about 4,600 tags and links) ships as one cached daily file; the deck's card tags (and art tags for its default illustrations) load per deck. Theme score N = distinct tagged cards (oracle) or illustrations (art), as in the prototype.
- **Layout (wide screens):** left = role profile + top tags; center = deck with a View / Group / Sort toolbar; right = sticky **card panel** (hovered card's image, the roles it fills, its oracle tags deepest first, its art tags; click a tag to highlight matching cards). Narrower screens fold the left column above the deck; phones open cards in a bottom sheet.
- **Views:** Text, Visual grid, Stacks. **Group:** Type, Role, Mana value, Color. **Sort:** Name, Mana value, Price. Saved per user (`profiles.tag_view`).
- **Card sheet:** tapping or clicking a card opens it immediately (image first) with big action buttons (commander, main/maybe, quantity, remove, add to another deck, copy name) and its tags; Prev / Next on desktop. Collapsible group headings with counts, quantity badges on tiles, summary bar (size, type counts, price).
- **Card details (3b):** rules text, P/T, faces, legality, rulings, fetched live from Scryfall; tags instead of buy links.
- **Built in 3a:** SQL `oracle_tag_tree()` (whole tree as one JSON value; the theme N values come from the latest `import_runs.counts.tagged_cards` / `tagged_illustrations`, which the importer now records) and `card_tags_for(ids)`. `/api/tag-tree` serves the tree with a one-day CDN cache. Logic: `src/lib/tags/tree.ts` (TagTree), `roles.ts` (STANDARD_ROLES, rolesOf), `src/lib/deck/grouping.ts`; hook `use-tag-data.ts`. UI: `deck-views.tsx` (Text / Grid / Stacks), `card-panel.tsx`, `card-sheet.tsx`, `card-tags.tsx`, `deck-toolbar.tsx`, `summary-bar.tsx`. Tests run with vitest (`vitest.config.mts` maps `@/`).
- **Built in 3b:** `src/lib/scryfall/card-details.ts` fetches a card live from Scryfall when its sheet opens (`/cards/search?q=oracleid:…`, then its `rulings_uri`), cached per visit, and normalizes it (faces, stats, legality with Commander first, rulings). `card-details.tsx` shows rules text per face (with `SymbolText`: mana symbols as icons, reminder text in italics), a Flip button when each face has its own image (modal/transforming DFCs; Rooms and split cards share one image), "✓ Legal in Commander", and collapsible "Legality in all formats" and "Rulings (N)".
- **Roles (3c):** dead slugs dropped. Card advantage has `notVia`: when a card is also Ramp, the "onto the battlefield" tags (consult-onto-battlefield, impulse-onto-battlefield, impulse-land, land-or-hand) don't count toward it, so land-fetchers count as Ramp only (David, Oct 19, 2026). Role profile (`role-profile.tsx`): bars, sliders (max 30, Lands 50), ⓘ explanations (hover on desktop, tap on phones), click a role to highlight its cards, Save as my defaults / Reset, custom roles from any tag. ## Phase 4 plan (agreed Oct 19, 2026)

- **Pool from our database** (David chose, not Scryfall search): one SQL function returns Commander-legal cards inside the commander's colors, not in the deck, carrying the role's or tag's tags (descendants included, same rules as the role profile), with their oracle tags, price and EDHREC rank. It takes the most-played end plus the least-played end, so Hidden gems has options. Overall "Suggest" uses the deck's top 15 theme tags.
- **Scoring ported exactly** from the prototype (`scorePool`): fit = shared theme-tag weight / total, normalized to the best candidate, + 0.12 per under-target role filled (capped at 1); popularity = 1 − min(rank, 20000)/20000. Styles: Best fit 0.6 fit + 0.4 pop; Hidden gems 0.65 fit + 0.35 (1 − pop), only cards with some fit; Budget 0.6 fit + 0.25 pop + 0.15 cheapness, hides cards over the price cap; Custom sliders. Top 24.
- **UI (David chose):** a Suggest panel above the deck, like Search (full-width grid, works on phones). Triggers: a 💡 button on each role row and top tag, and a **Suggest** header button for overall picks; clicking the role or tag name still highlights. Each card shows why (fills role, up to 4 shared tags), price, EDHREC rank, and big Add to main / Add to maybe / Not for this deck buttons.
- **Per deck** (spec): `decks.suggest_settings` (style, price cap, custom weights) and `decks.dismissed_suggestions` (oracle ids), with "Show dismissed".
- Steps: **4a** pool function + scoring module (tested) + panel with triggers and add; **4b** the four styles, saved per deck; **4c** dismiss + Show dismissed, and a side-by-side check on the Omo deck against EDHREC (the spec's success test). Bracket filtering waits for Phase 5.
- **Built in 4a:** migration 0012 `suggestion_pool(p_slugs, p_identity, p_exclude, p_lands, p_top 150, p_tail 60)`, plpgsql on purpose (as one SQL statement it got a slow generic plan, 8 s) and with joins rather than `= any(10,000 ids)`. Warm calls take 0.3-0.5 s; the first call after a quiet spell can take ~8 s while the free-tier database loads the tag tables. Scoring in `src/lib/suggest/score.ts` (all four styles, tested; 4a uses Best fit). `suggest-panel.tsx` (two columns on phones), opened by **Suggest** in the header (overall: descendants of the top 15 gameplay themes), 💡 on role rows (`role.tagSet`, Lands via `p_lands`; only cards whose `rolesOf` includes the role, so Targeted removal skips wipes) and 💡 on oracle top tags (the tag plus descendants). Scored against the top 15 gameplay themes even in Flavor mode (pool cards carry oracle tags only). Cards on any board, maybeboard included, are left out. Hovering a suggestion shows it in the card panel.
- **Built in 4b:** migration 0013 `decks.suggest_settings` (`readSuggestSettings` clamps it: price cap $0.25-100, fit/price 0..1, popularity -1..1), saved half a second after a change by `use-suggest-settings.ts` (not part of Ctrl+Z). Each card shows "fit N · played N" (0-100). Empty results say why (price cap, or no lesser-played fits).

Overall Suggest asks for the exact theme slugs in Specific mode (descendants only in Broad); the panel retries once when the database times out on a cold start (PostgREST stops at about 8 s).
- **Staples fix (David, Nov 7, 2026):** Sol Ring and Arcane Signet sank because fit counts only theme tags and role tags aren't themes. - **Dev server gotcha:** after editing a module the page imports deep down (e.g. `src/lib/suggest/score.ts`), Fast Refresh sometimes keeps the old copy. If behavior doesn't match the tests, stop dev, `rm -rf .next`, start again.

## Phase 5 plan (agreed Oct 19, 2026)

- **Rules (Oct 2026; tutor limits were removed in the Oct 2025 update):** Game Changers 0 / 0 / up to 3 / any / any for brackets 1-5; mass land denial only in 4-5; extra turns none in 1, "a few, not chained" in 2-3, any in 4-5; two-card combos none in 1-2, "not early-game" in 3, any in 4-5. Stored as data in one config file, not hard-coded.
- **Data:** Game Changers = `cards.game_changer` (53, from Scryfall daily); mass land denial = oracle tag `mass-land-denial`; extra turns = oracle tag `extra-turn`; **two-card combos imported daily** from Commander Spellbook (David chose this over live API calls): the import job streams `json.commanderspellbook.com/variants.json` (~693 MB) and keeps only 2-card combos.
- **David's choices:** "a few" extra-turn cards = **up to 2** (3+ puts the deck at 4+); a combo Spellbook tags **Ruthless counts as 4+**, any other 2-card combo as at least 3; **default target = 3 (Upgraded)** for existing decks and new decks until changed.
- The estimate shows only what the cards prove ("2 or lower", "at least 3", "4+") and never claims 5 (cEDH is intent, not a card list).
- **Combo rule changed after the import (David, Oct 21, 2026): follow Spellbook's rating of each combo** (Ruthless 4, Spicy/Powerful 3, Oddball/Core 2, Exhibition no effect; unrated 3). Spellbook rates loops that don't win alone (Gravecrawler + Phyrexian Altar, Felidar Guardian + Restoration Angel) as Exhibition. Every combo still shows as info.
- **Built in 5a:** migration 0015 `combos` (id, card_a < card_b, results text[], bracket_tag, requires, popularity; read-only for everyone), `combos_within(ids)`; 0016 `import_runs.source` (scryfall | combos; `oracle_tag_tree` reads Scryfall runs only); 0017 `decks.target_bracket` default 3, not null (the column already existed from 0003, nullable, so 0015's add-column was skipped). `scripts/import-combos.mts` (`npm run import:combos`, `stream-json`; ~1 min 45 s locally) runs nightly after the Scryfall import. Rules as data in `src/lib/brackets/rules.ts`; `evaluate.ts` (`estimateBracket` returns a floor 1-4 plus findings, `estimateLabel`: "2 or lower" / "3" / "4+", `overTarget`), tested.
- **Built in 5b:** `bracket-panel.tsx`: header **Bracket N · cards X** badge (amber with ⚠ when the cards go above the target) that opens the Bracket panel (five target buttons with blurbs, saved per deck by `use-bracket.ts` half a second after a change, not Ctrl+Z; every finding with "any" / "N+" chips, over-target ones shaded). ## Scryfall data facts (learned the hard way in the prototype)

- **Bulk list**: `GET https://api.scryfall.com/bulk-data`. Use types `oracle_cards`, `oracle_tags` and `art_tags`.
- **Tag files are JSONL** (one JSON object per line), possibly gzip-compressed (first bytes `1f 8b`). The listing may name the link `jsonl_download_uri` rather than `download_uri`. Check both and handle both formats.
- **Browsers can't download bulk files** (CORS), but they can call the search API. All bulk downloads happen in the server job.
- **Tag object**: `{ id, slug, label, type, description?, aliases?, parent_ids?, child_ids?, taggings: [{ oracle_id | illustration_id, weight, annotation? }] }`.
  - Oracle tags key on `oracle_id`, shared by every printing of a card.
  - Art tags key on `illustration_id`, so they're printing-specific. Use the deck's chosen printing.
  - Art tags have `type: "illustration"` in the file; we store them as `kind = 'art'`.
- **The tag tree** exists (24,477 links in Oct 2026, mostly in the art-tag tree; the prototype's ~4,600 was oracle-only) and may be stored as `parent_ids`, `child_ids` or both. Merge both directions. **Each card is tagged at ONE level only**: a card with *death trigger* is not also tagged *triggered ability*. Parents are implied.
- **Search syntax**: `otag:<slug>` for oracle tags, `art:<slug>` for art tags, plus `id<=BG f:commander game:paper`, `order=edhrec`. A search with no results returns HTTP 404; treat it as empty.
- **Rate limit**: stay at or under 10 requests a second (the prototype waits 110 ms between calls). Send `Accept` and a descriptive `User-Agent` from the server.
- **Popularity**: `edhrec_rank` is on every card object, so EDHREC itself never needs scraping. Today's price is `prices.usd`, refreshed daily; there's no price history.

## Logic to port from the prototype

Find these in `prototype/tag-deck-builder.html`:

- **Roles** (`STANDARD_ROLES`): each role maps to tag slugs and includes all descendant tags. Lands come from the type line. Targeted removal excludes cards that are board wipes. Defaults: Lands 37, Ramp 10, Card advantage 10, Targeted removal 8, Board wipes 3, Protection 3, Recursion 2. Default targets don't change with bracket, except Tutors (added Nov 7, 2026; see Smart Cutter); each user can save their own defaults, and add a custom role from any tag.
- **Theme tags** (`themeTags`): count tags across nonland cards (commander counts double and is pinned), excluding role tags. Score = count × ln(1 + N / tag size). Commander tags show first.
- **Gameplay / Flavor switch**: Gameplay = oracle tags minus wording/name tags. Flavor = art tags plus wording/name oracle tags (`FLAVOR_ORACLE`, `isFlavorOracle`). Always hidden: `MECHANIC_NOISE` (static, keyword and mana ability, vanilla variants).
- **Specific / Broad switch**: Specific = tags exactly as applied, listed deepest first. Broad = also roll each tag up to all its ancestors. **Never drop a tag in Specific**; David explicitly rejected that.
- **Sort switch**: Relevance (the score) or Count (raw hits). It picks the top 24; Specific then reorders by depth.
- **Tag tree hover card**: parents, then the tag (highlighted), then its subtags, with in-deck counts.
- **Hidden tags**: a user can hide any tag. Store keys as `o:<slug>` or `a:<slug>` and save them per user.
- **Suggestions** (`suggest`, `scorePool`): the pool comes from Scryfall search for the clicked role or tag, in the commander's color identity, pages 1–2 by EDHREC rank plus the least-played end. Fit = shared theme-tag weight (normalized) + 0.12 per under-target role filled. Styles:
  - **Best fit:** 0.6 fit + 0.4 popularity.
  - **Hidden gems:** 0.65 fit + 0.35 (1 − popularity).
  - **Budget:** fit and popularity, plus a price cap.
  - **Custom:** sliders for each factor.
  - Every suggestion shows *why* (shared tags, roles filled).
